# Отчёт по лабораторной работе №4

## Данные и подготовка

Использован набор `german.csv`: 1000 наблюдений, 20 входных признаков и целевая переменная `Creditability`. Файл разделён точкой с запятой (`sep=";"`). Целевая переменная содержит два класса: 0 и 1; положительным классом считался класс 1. Признаки представлены числовыми кодами и числовыми значениями. Пропусков в исходном наборе не обнаружено.

Для итоговой оценки использовано стратифицированное разделение на обучающую и тестовую части в отношении 80:20 (`test_size=0.2`, `random_state=42`). Стратификация сохраняет доли классов. Для сравнения моделей внутри обучающей части дополнительно выделена валидационная часть: 80% обучающей выборки для обучения и 20% для проверки (`random_state=42`, также со стратификацией). Тестовая часть не использовалась при выборе параметров.

Для деревьев и градиентного бустинга масштабирование не применялось, поскольку эти алгоритмы не требуют стандартизации числовых признаков. Для MLP использовались медианная импутация и `StandardScaler` в конвейере; это преобразование обучалось только на подвыборке обучения. В исходных данных пропусков нет, поэтому импутация фактически служила защитой конвейера.

## Гипотезы и эксперименты

Проверялись следующие гипотезы:

1. Random Forest должен дать устойчивую базовую ансамблевую модель за счёт усреднения большого числа деревьев.
2. Extra Trees с более случайным выбором разбиений может уменьшить дисперсию, но потенциально увеличить смещение.
3. Gradient Boosting способен выявлять последовательные зависимости между ошибками слабых деревьев; проверялись глубина, число итераций и скорость обучения.
4. HistGradientBoosting проверялся как более быстрый вариант градиентного бустинга.
5. MLP проверялась как полносвязная нейронная сеть; для неё масштабирование признаков обязательно.

Все эксперименты сравнивались на одной и той же валидационной выборке. Порог бинаризации вероятности для Accuracy, Precision, Recall и F1 установлен равным 0.5. ROC-AUC рассчитывался по непрерывным вероятностям положительного класса.

Дополнительно для Gradient Boosting проверялись сочетания глубины дерева (1, 2, 3) и `learning_rate` (0.03, 0.05, 0.08) при 250 итерациях. Лучшее из проверенных сочетаний на валидации: `max_depth=1`, `learning_rate=0.08`.

## Выбранная модель

Выбрана модель `GradientBoostingClassifier` со следующими параметрами:

- `n_estimators=250`;
- `learning_rate=0.08`;
- `max_depth=1`;
- `min_samples_leaf=5`;
- `subsample=0.8`;
- `random_state=42`.

Глубина 1 означает, что базовые деревья являются пнями (одно разбиение). Небольшая глубина ограничивает сложность каждого слабого алгоритма, а последовательное добавление 250 деревьев позволяет постепенно улучшать качество. `learning_rate=0.08` задаёт вклад каждого нового дерева. `subsample=0.8` означает, что на очередной итерации используется случайная доля обучающих объектов, что добавляет стохастичность и может снижать переобучение.

На валидации модель показала наибольший ROC-AUC среди проверенных конфигураций. На независимой тестовой части получен ROC-AUC 0.8273. В контрактной функции вероятности берутся из `predict_proba`, а метки формируются порогом 0.5.

## Выводы и ограничения

Наилучший результат среди проверенных конфигураций показал Gradient Boosting с неглубокими базовыми деревьями. Random Forest также дал сильный результат, тогда как Extra Trees, HistGradientBoosting и MLP в проведённых конфигурациях уступили по ROC-AUC.

Результат показывает, что для данного набора данных последовательное исправление ошибок неглубоких деревьев оказалось эффективнее проверенных альтернатив. MLP чувствительна к масштабу признаков и настройкам архитектуры; одна проверенная архитектура не позволяет сделать вывод обо всех нейронных сетях. Аналогично, ограниченный набор параметров не гарантирует глобально оптимальную конфигурацию.

Оценка зависит от конкретного случайного разбиения и состава данных. Набор небольшой, поэтому метрики могут заметно меняться при другом split. Значение ROC-AUC на тесте нельзя трактовать как гарантию такого же качества на новых внешних данных.

## Воспроизводимость

- Файл данных: `german.csv`, разделитель `;`.
- Внешний split: `train_test_split(test_size=0.2, random_state=42, stratify=y)`.
- Внутренний split для сравнения: `train_test_split(test_size=0.2, random_state=42, stratify=y_train)`.
- Seed моделей: `42`.
- Порог бинаризации: `0.5`.
- Используются `numpy`, `pandas` и `scikit-learn`.

Для воспроизведения итоговой оценки необходимо использовать тот же файл `german.csv`, разделитель `;` и разбиение `train_test_split(test_size=0.2, random_state=42, stratify=y)`, после чего вызвать `run_ensemble_experiment` из `ensemble_models.py`, передав полученные train/test части в `EnsembleInput`. Параметры модели и seed зафиксированы в контрактной функции. Файл `experiment_results.json` содержит результаты сравнения моделей на валидационной части и итоговые метрики выбранной модели на тестовой части. Файлы `grader_contracts` менять не требуется.
